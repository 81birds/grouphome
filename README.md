# グループホーム アプリ(試作)

グループホームのスタッフ用 Web アプリです。ブラウザだけで動き、データは Supabase に保存されます。

## 画面一覧

最初に合言葉を入力すると、各画面のアイコンが表示されます。

## サンプルデータ(ポートフォリオ用)

- 架空のサンプルデータ(利用者さん・スタッフ・勤務表・日々の記録・バイタル・食事・備品など)が入っています。実在の人の情報は入っていません
- 見に来た人が自由に追加・変更しても、毎日 3:00(日本時間。pg_cron)に自動でサンプルデータにもどります。開発者の画面(`dev.html`)の「サンプルデータにもどす」でもすぐもどせます
- サンプルデータは DB の `demo.snapshots` にテーブルごとに保存しています(API からは見えません)。もどすときは `demo.restore` が、いまのデータを消して保存したデータを入れ直します。合言葉はそのままです
- もどすときは、日付を 7 の倍数の日数だけずらして今日に合わせます(曜日は変わらないので、土日の昼食・平日の通所・勤務表もそのまま)。ずらしきれない 0〜6 日分の日々の記録とバイタルは、1 週間前の分を写して埋めます
- サンプルデータを作り直したときは、Supabase の SQL Editor で `select * from demo.save_snapshot('サンプルデータの今日');` を実行して保存し直します(画面からは保存できません)
- 画面から変えたものは、変更の履歴(`demo.change_log`)に残り、開発者の画面に出ます。開発者の画面で「この端末を自分にする」としたブラウザの変更は「自分」、それ以外は「見た人」(ブラウザごとの記号つき)になります。見分けはブラウザが付けるヘッダー(`x-gh-actor`・`x-gh-device`)によるので、デモ用の目安です
- 新しいテーブルを足したときは、`demo.tables()` にも足します(`sql/2026-11-17_demo_reset.sql`)

## はじめての準備

### 1. Supabase

1. Supabase で新しいプロジェクトを作る(リージョンは Tokyo がおすすめ)
2. **SQL Editor** で `sql/2026-10-10_init.sql` を実行する
3. 同じく **SQL Editor** で合言葉を登録する(合言葉はファイルに残さず、ここで直接実行する)

   ```sql
   insert into public.app_secret (id, passcode_hash)
   values (1, extensions.crypt('ここに合言葉', extensions.gen_salt('bf')))
   on conflict (id) do update set passcode_hash = excluded.passcode_hash;
   ```

   合言葉を変えるときも同じ SQL を実行します。各端末で一度ログアウトされます

4. **Project Settings → API Keys** の Project URL と Publishable key を `js/config.js` に書く

### 2. ローカルで確認

VS Code でこのフォルダを開き、`index.html` を右クリック → **Open with Live Server**。

### 3. GitHub と Vercel

1. GitHub に新しいリポジトリ(Private 推奨)を作って push する
2. Vercel で **Add New → Project** からそのリポジトリを選ぶ(Framework Preset は **Other**、ビルド設定は空のまま)
3. 以降は `main` に push するたびに自動でデプロイされます

## しくみ

- **フロントエンド**: ビルド不要の静的 HTML。共通のデザインは `css/common.css`、共通の処理は `js/common.js` にまとめています
- **データベース**: Supabase(PostgreSQL)
  - テーブルへの直接アクセスは許可していません。画面からは `rpc` で関数(`get_residents` など)を呼びます
  - どの関数も最初に `check_passcode` で合言葉を確認します。合言葉はブラウザの localStorage に保存されます
- **スワイプで戻らない**: 表の横スクロールや時刻のホイールで誤って前の画面に戻らないよう、`css/common.css` で画面全体に `overscroll-behavior-x: none` を付けています(Chrome・Edge・Firefox・Android で有効)
  - そのため、これらのブラウザではスワイプで前の画面に戻れません。画面の移動は上部タブを使います
  - iPhone・iPad・Mac の Safari では、ブラウザの戻るスワイプはページ側から止められません。気になるときは、iPhone はホーム画面に追加して開く、Mac はトラックパッドの設定で「ページ間をスワイプ」をオフにします

## データベースの変更

- 変更は `sql/YYYY-MM-DD_内容.sql` という名前で追加し、Supabase で実行してからコミットします
- 過去の SQL ファイルは書き換えません

開発のルール(デザイン・画面の追加方法など)は `CLAUDE.md` にまとめています。
